# IP/节点卫生：换号期的节点纪律

## 核心原理

服务端风控能看到的只有**每个请求的源 IP**。没有"事后察觉你换过节点"的能力——只有"某个 IP 有没有向这个账号发过请求"这个记录。

所以节点卫生 = **控制哪些 IP 有资格碰到你的账号**：

- 账号的 IP 历史 = 每次请求的来源集合。混入真实家庭 IP 或其他节点 = 账号被打了"多地/多网"标记
- 只在用 Claude 时开静态住宅代理是完全可行的模式——账号 IP 历史反而更干净（永远只见同一个住宅出口）
- 风险不在"开关代理"本身，在**关代理那一刻有没有 Claude 流量漏出去**

## 正确循环（每次使用）

```
1. 开代理 → 2. preflight.ps1 确认出口(必须过)→ 3. 使用 Claude
→ 4. 关干净所有 Claude 出口面 → 5. 才允许关代理/切节点
```

第 4 步的"关干净"完整定义：

- **所有 `claude.exe` 进程退出**(CLI 会话全关)
- **Claude Desktop 退出**(如果装了)
- **所有打开的 claude.ai 标签页关闭** —— 最容易漏的：开着的页面里 Intercom/Sentry/心跳 JS 会持续发请求，代理一断它们就走真实 IP
- 无痕窗口天然满足这点：窗口一关，连 cookie 带 JS 全死

顺序反了 = 真实 IP 打进账号历史。

## 一号一节点，少漂移

- 选定的节点**固定用到底**。账号锁在一个 IP/ASN/城市 = 最像真人
- 漂移容忍度：同 ASN 同城市换 IP（重启光猫那种）= 可接受；跨城市/跨国跳 = 软信号
- 旧号死过的 IP 段**不要**给新号用——哪怕同一家供应商，换个入口

## 代理工具的形态决定 CLI 走不走代理

- **TUN/全局模式**(看到 `198.18.x.x` 这类虚拟网卡地址就是）:CLI、浏览器全走 → 安全
- **系统代理/浏览器扩展代理**:**只管浏览器，管不到 `claude.exe`** → CLI 请求会漏真实 IP！用这类工具时必须确认 CLI 进程环境/路由也走代理
- 验证方法永远只有一个：开代理后 `curl http://ip-api.com/json` 看出口，**在准备跑 Claude 的同一个终端里测**

## 出口质量验收（选节点时）

```powershell
curl http://ip-api.com/json/?fields=query,isp,as,hosting,proxy,mobile
```

- `hosting=true` → 上游被标机房，**换节点**。住宅代理也会翻车：供应商的上游 ASN 被标 hosting(实测遇到过：名义住宅、ip-api 标机房）
- `proxy=true` → 被识别为代理，弱住宅；能接受但不是最好
- 双验：再用 `ip.net.coffee/claude/`(或同类 Claude 视角检测）过一遍——风控看的是它家情报库的口径，不是购买页面上写的"静态住宅"

## 泄漏面（一般不用管，知道就行）

- **WebRTC**：浏览器内可泄露局域网/真实 IP —— 用无痕+现代浏览器默认策略即可，真正的风险仍是"开着 claude.ai 标签页切代理"
- **DNS**:TUN/全局代理接管 DNS 就不漏；只在浏览器挂代理时，DNS 走本地也不碰 anthropic 域的话无伤大雅
- **本机其它软件**：不访问 anthropic/claude 域的流量与账号无关，随便走真实 IP

## 登录那一次的特别注意

OAuth 登录 = CLI 起本地回调 + 浏览器跳 claude.ai，**两个方向的流量都在那一刻产生**。所以登录前：

1. 代理已在目标节点
2. `preflight.ps1` 过
3. 无痕/干净浏览器里完成整个 OAuth 跳转
4. 窗口关闭前不切代理
